Задача: Реализовать страницу авторизации (Login) и клиентский слой аутентификации на React (TypeScript, Vite) для взаимодействия с backend на Frappe Framework с использованием сессионных cookie (sid).

Архитектурный контекст:
1. Авторизация работает на базе сессионной Cookie `sid`, которую Frappe автоматически устанавливает при успешном запросе на `/api/method/login`.
2. Все защищенные методы требуют передачи заголовок `X-Frappe-CSRF-Token` и параметра `credentials: 'include'` в каждом HTTP-запросе.
3. Проверка текущей сессии выполняется через запрос к `/api/method/frappe.auth.get_logged_user`.
4. Логаут выполняется через запрос к `/api/method/logout`.

Что нужно создать и реализовать:

1. API-клиент (`src/api/auth.ts`):
   - Написать обертку над `fetch` с параметром `credentials: 'include'`.
   - Реализовать автоматическое извлечение CSRF-токена из cookie `csrf_token` (или `window.frappe.csrf_token`) и его добавление в заголовок `X-Frappe-CSRF-Token` для запросов POST/PUT/DELETE.
   - Написать методы для авторизации:
     * `login(usr, pwd)` -> POST `/api/method/login` с телом `{ usr, pwd }`.
     * `logout()` -> POST `/api/method/logout`.
     * `getLoggedUser()` -> GET `/api/method/frappe.auth.get_logged_user`.

2. Состояние авторизации (Auth Context / Zustand):
   - Создать React Context (`AuthProvider` и хук `useAuth`) или Zustand-стор (`useAuthStore`).
   - Состояние должно содержать:
     * `user: string | null` (имя/email пользователя или null, если не авторизован).
     * `isLoading: boolean` (флаг первичной проверки сессии).
     * `error: string | null`.
     * функции `login(usr, pwd)`, `logout()`, `checkAuth()`.
   - При монтировании приложения вызвать `checkAuth()` для определения, активна ли текущая сессия. Если `getLoggedUser()` возвращает пользователя (и это не "Guest"), установить `user`.

3. Компонент страницы входа (`src/pages/LoginPage.tsx`):
   - Форма с полями `usr` (email/логин) и `pwd` (пароль).
   - Валидация полей (непустые значения).
   - Индикация загрузки на кнопке во время отправки запроса (`submitting`).
   - Вывод ошибок авторизации (например, "Неверный логин или пароль").
   - При успешном входе делать редирект на главную страницу `/` или обновлять состояние.
   - Стилизовать форму с помощью Tailwind CSS (или имеющейся CSS-библиотеки) с аккуратной версткой по центру экрана.

4. Защищенный роут (`src/components/ProtectedRoute.tsx`):
   - Компонент-обертка для роутов, доступных только авторизованным пользователям.
   - Если `isLoading === true` -> показывать спиннер/загрузку.
   - Если `user === null` -> перенаправлять на `/login`.
   - Если пользователь авторизован -> рендерить дочерние компоненты (`<Outlet />` или `children`).

Требования к коду:
- Строгая типизация TypeScript (без `any`).
- Правильная обработка ошибок и HTTP-статусов (401, 403).
- Чистая структура файлов, готовая к использованию в production.
